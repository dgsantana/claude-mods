# omp-port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Deviation note:** per the user's global CLAUDE.md, this plan states files, interfaces, test
> behaviour (prose) and verification commands — not written-out code. This overrides the
> writing-plans skill's full-code-block mandate.

**Goal:** Ship the `omp-port` Claude Code plugin (APPEND_SYSTEM, AGENTS.md, rules, TTSR, advisor) plus a Bun nerd status line, in a public marketplace repo `dgsantana/claude-mods`.

**Architecture:** One plugin of function hooks (`plugins/omp-port`). Pure logic (frontmatter, layer merge, TTSR matching, pricing) lives in `$`-free modules unit-tested with `bun test`; thin hook modules wire it to the engine and are tested with `claude plugin test`. The status line is a standalone Bun script.

**Tech Stack:** TypeScript, Claude Code function-hook API (build 2.1.289), Bun 1.3.14, optional `ast-grep`, `gh`.

**Spec:** `docs/superpowers/specs/2026-10-04-omp-port-design.md`

## Global Constraints

- Works on Linux and Windows: no hard-coded `/`; join paths with a helper that accepts both separators; home = `USERPROFILE` ?? `HOME`.
- Hook modules: no Node, no DOM, no npm imports; only plugin-local files, `'claude-code'` types, `$`. No `import()`.
- Never read `~/.omp/...`.
- Layer order: builtin → `~/.agents/` → `.agents/` dirs from repo root down to cwd (nearest wins).
- Rule store dir `.agents/rules/`; mod files under `.agents/mods/` (`APPEND_SYSTEM.md`, `config.json`).
- Every hook falls through to `next(e)` on its own error; log once with `$.ui.log`.
- Section ids prefixed `omp-port:`; `scope: 'session'`.
- Plugin name `omp-port`, marketplace `dgsantana`, repo `claude-mods` (public).
- Test split: pure modules → `plugins/omp-port/unit/*.spec.ts` (`bun test`); engine → `plugins/omp-port/tests/*.test.ts` (`claude plugin test`).

## Review Focus

1. **Windows paths** — `C:\Users\x\.agents\rules\a.md`, mixed separators in `file_path`; globs like `*.rs` must still match. Test in Task 3 and Task 5.
2. **Malformed rule frontmatter** — unclosed `---`, invalid YAML, scalar where list expected; file must load with empty metadata or be skipped with one log, never crash a session. Test in Task 2.
3. **Huge Write payloads** — a 2 MB `content` must not stall a tool call; regex runs with a size cap and AST via stdin with a timeout. Test in Task 6.
4. **No repo / cwd outside git** — layer discovery must still find global `~/.agents/` and cwd `.agents/`. Test in Task 3.
5. **Advisor fork failing or budget already exceeded at session start** — no fork call, no band, status explains. Test in Task 8.

### Task 2: Frontmatter + rule normalization (pure)

**Files:**

- Create: `plugins/omp-port/hooks/rule.ts`
- Test: `plugins/omp-port/unit/frontmatter.spec.ts`, `unit/rule.spec.ts`

**Interfaces:**
- `parseFrontmatter(text: string): { data: Record<string, unknown>; body: string; warning?: string }`
- `type Rule = { name; path; content; description?; globs?: string[]; alwaysApply?: boolean; condition?: string[]; astCondition?: string[]; scope?: string[]; interruptMode?: 'never'|'prose-only'|'tool-only'|'always'; enabled: boolean; source: 'builtin'|'global'|'project' }`

Tests pin:
- YAML subset: plain/quoted scalars, booleans, flow arrays `[a, "b"]`, block sequences, comments; keys hyphen→camelCase.
- Fallback: unparseable YAML → `key: value` line parse, each value re-parsed; `warning` set.
- No / unclosed frontmatter → empty data, full body.
- `ttsr_trigger`/`ttsrTrigger` → `condition`; string vs list normalised to list; comma-separated `scope` string split; tolerant `"text","thinking"` form.
- `name` = basename sans `.md`/`.mdc`, from both `/` and `\` paths.
- `enabled: false` respected.
- All 27 vendored builtins parse without warning (read from disk in the spec).
